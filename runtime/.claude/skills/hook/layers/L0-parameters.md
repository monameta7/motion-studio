## 🧭 Layer 0 — استخراج پارامترها

| پارامتر | توضیح | مثال |
|---|---|---|
| `TOPIC` | موضوع خام | «هوش مصنوعی برای فروشگاه اینترنتی» |
| `NICHE` | حوزه کاری | آموزشی / فروشگاهی / خدماتی / برند شخصی / سرگرمی / صنعتی |
| `GOAL` | هدف اصلی | یکی از ۶ گزینه پایین |
| `PRESENCE_MODE` | حضور بازیگر | `presenter` (پیش‌فرض) / `narrator_only` |
| `NARRATIVE_MODE` | روایت انیمیشنی (تشخیص خودکار) | `off` (پیش‌فرض) / `narrative_ad` / `narrative_story` |
| `MODE` | حالت کار | `create` (پیش‌فرض) / `diagnose` |
| `OUTPUT_MODE` | میزان جزئیات خروجی (فقط در create) | `production` (پیش‌فرض) / `full` |

### ۶ گزینه GOAL و تعریف موفقیت اجرایی

GOAL = **یک اصلی** + حداکثر **یک فرعی** از همین شش. جدول‌های Layer 2، 5.5 و 8 با GOAL اصلی کار می‌کنند؛ فرعی فقط در V4 و واکنش‌های و۱–و۳ دیده می‌شود.

| GOAL | تعریف موفقیت اجرایی |
|---|---|
| `view` | دسترسی و ویوی معنادار نسبت به اندازه‌ی پیج و محتوای مشابه |
| `follow` | فالوهای منتسب به محتوا، در صورت دسترسی؛ نسبت به ریلزهای مشابه و تعداد بازدیدکنندگان غیرفالوور تفسیر شود |
| `sale` | کلیک روی لینک بایو یا پیام دایرکت خرید |
| `cta_engagement` | کامنت/دایرکت/تماس (تعامل مستقیم قابل ردیابی) |
| `save` | سیو متناسب با محتوای مشابه؛ بدون آستانه‌ی عمومی قطعی |
| `share` | شیر متناسب با محتوای مشابه؛ بدون آستانه‌ی عمومی قطعی |

### تشخیص خودکار GOAL

```
IF TOPIC حاوی خدمت مشاوره‌ای / فروش B2B      → cta_engagement
IF TOPIC حاوی محصول فیزیکی قابل خرید         → sale
IF TOPIC حاوی آموزش گام‌به‌گام / چک‌لیست      → save
IF TOPIC حاوی داستان / تجربه شخصی            → follow
IF TOPIC حاوی نظر جنجالی / ترند              → view (فرعی: share)
IF TOPIC حاوی سؤال از مخاطب / پرسش تعاملی    → cta_engagement
IF TOPIC هشدار درباره‌ی اشتباه رایج و پرخطر   → share (فرعی: save)
# پیشنهاد خودکار فقط فرضیه‌ی شروع است؛ درخواست صریح کاربر، هدف کمپین و وضعیت پیج اولویت دارند. اگر چند ردیف منطبق‌اند، انتخاب را با خروجی مورد انتظار بسنج، نه صرفاً اولین واژه‌ی موضوع.
DEFAULT                                       → follow
```

### 💎 دروازه‌ی ارزش ایده V1–V3 و V5 — اولین دروازه

این دروازه کیفیت ایده را بررسی می‌کند، نه اینکه موضوع را با یک معیار خشک رد کند. اگر پاسخ ضعیف بود، ابتدا زاویه، مثال یا کاربرد را بهتر کن.

```text
V1 — تغییر یا تصمیم مخاطب
     بعد از دیدن محتوا چه کاری را بهتر انجام می‌دهد یا چه تصمیمی را دقیق‌تر می‌گیرد؟
     گزارش: «تغییر مورد انتظار: ...»

V2 — اهمیت دانستن
     دانستن این نکته چه اثری بر زمان، هزینه، کیفیت، امنیت، اعتماد یا انتخاب مخاطب دارد؟
     گزارش: «اهمیت برای مخاطب: ...»

V3 — زاویه و تازگی
     چه چیزی در این روایت، مثال، روش یا ترکیب اطلاعات با محتوای عمومی و تکراری فرق دارد؟
     گزارش: «زاویه‌ی تازه: ...»

V4 — محرک توجه (یکی از گزینه‌ها، نه شرط اجباری)
     سؤال ملموس، تضاد، مقایسه، عدد، کشف، آزمایش، نتیجه یا باور غلط.
     گزارش: «محرک توجه: ... · دلیل جذابیت: ...»

V5 — ارزش متناسب با هدف (برای آموزش/اطلاع‌رسانی: ارزش آموزشی ممتاز)
     آموزش: مخاطب چه دارایی دانشی قابل استفاده‌ای می‌برد؟ (روش، معیار، فرمول، چک‌لیست، کشف، مقایسه یا مثال مرحله‌به‌مرحله)
     سرگرمی/روایت: تجربه، لذت، همذات‌پنداری یا دیدگاه معناداری که محتوا تحویل می‌دهد چیست؟
     گزارش: «ارزش تحویلی: ... · کاربرد/تجربه: ... · مثال/اثبات در صورت نیاز: ... · محدودیت: ...»
```

**قانون تصمیم:** V1 تا V5 را متناسب با هدف و نوع محتوا تحلیل کن؛ آزمون «دارایی دانشی» برای محتوای آموزشی/اطلاعاتی الزامی است. ضعف قابل اصلاح به بازطراحی زاویه، روش یا مثال منجر می‌شود؛ نه رد خودکار موضوع. موضوع فقط وقتی کنار گذاشته می‌شود که پس از بازطراحی نیز برای مخاطب مشخص، ارزش یا ارتباط روشنی نداشته باشد.

**جست‌وجو برای شناخت فضای رقابتی و راستی‌آزمایی است، نه آزمون حذف موضوع.** اگر پاسخ در وب موجود است، بررسی کن چه مثال، روش، اثبات، زمینه یا کاربردی می‌توانی بهتر ارائه کنی. صرف وجود نتیجه‌ی مرتبط در جست‌وجو، دلیل رد موضوع نیست. معیار کامل V5 در `references/publish-rules.md` و `references/v2-core-standard.md` آمده است.



### 🚦 دروازه‌ی داده‌ی Case Spine — قبل از هر لایه‌ی دیگر

**فقط وقتی اجرا می‌شود که ورودی به یک نتیجه‌ی واقعی مشتری اشاره دارد.** چهار سؤال، همین‌جا و همین لحظه:

```
[ ] D1  عدد یا نتیجه‌ی واقعی در دست است؟ (نه «می‌شود گرفت» — همین حالا)
[ ] D2  شاهد خام موجود است؟ اسکرین‌شات داشبورد، سند، اندازه‌گیری  → دروازه C2
[ ] D3  صدای سوم‌شخص موجود است؟ تستیمونیال، کامنت، پیام مشتری     → دروازه C4
[ ] D4  اجازه‌ی انتشار نام و داده‌ی مشتری هست؟
```

**هر چهار پاس → Case Spine مجاز است.**
**هر کدام فِیل → Case Spine از نردبان حذف می‌شود.** به کاربر در یک خط اعلام کن کدام مورد کم است و با چارچوب بعدی نردبان ادامه بده. پیشنهاد جایگزین: همان محتوا با چارچوب PAS یا Contrast، بدون ادعای نتیجه‌ی مشتری.

> این دروازه عمداً در Layer 0 است. در نسخه‌های قبلی بررسی C2 و C4 در Layer 5 انجام می‌شد و نتیجه‌اش این بود که پنج لایه کار انجام می‌شد و بعد دور ریخته می‌شد.

**خروجی این لایه:** «GOAL منتخب: X، دلیل: ...»

**قانون استخراج:** اگر کاربر فقط `TOPIC` داد، `NICHE` و `GOAL` را **خودت استنباط کن** و با دلیل اعلام کن — **نپرس، مگر اینکه TOPIC واقعاً مبهم باشد** (یک کلمه‌ی تک بدون زمینه).

### تشخیص خودکار `PRESENCE_MODE`

اگر ورودی شامل این‌ها بود → `narrator_only`:
«بدون بازیگر» · «بدون حضور» · «فقط روایت» · «روایتگر» · «voice-over» · «انیمیشن» · «موشن گرافیک» · «مستند» · «تایم‌لپس» · «process video» · «فقط تصویر» · «بدون چهره»

در غیر این‌صورت `presenter`. اگر مبهم بود → **بپرس**.

### تشخیص خودکار `NARRATIVE_MODE`

طبق گام ۲ درخت بارگذاری (در `SKILL.md`) از قبل تعیین شده است. اگر `!= off` بود، `narrative.md` در این مرحله از قبل بارگذاری شده — قواعد زیرحالت و بودجه‌ی بیت‌ها را از آن بردار.

### تعیین `OUTPUT_MODE`

- پیش‌فرض `production` است: فقط دارایی درخواستی و اجزای لازم برای اجرای آن ارائه شود.
- `full` با درخواست تحلیل کامل/بسته‌ی کامل یا وقتی پیچیدگی و ریسک موضوع جزئیات را ضروری می‌کند انتخاب می‌شود.
- اگر کاربر فقط ویس‌اور می‌خواهد، خروجی فقط ویس‌اور است؛ `production` به معنی تحویل خودکار تمام بخش‌های بسته نیست.

### تشخیص خودکار `MODE == diagnose`

طبق گام ۱ درخت بارگذاری تعیین شده است. در این مود **هیچ لایه‌ای اجرا نمی‌شود**؛ خروجی یک تشخیص و یک اصلاح تک‌متغیره است، نه سناریوی نو. ورودی‌های لازم و جدول تشخیص در `diagnose.md` بخش ۱.

### کارت برند — `BRAND_CARD` (v2.8)

برای هر نیچ و برندی اجرا می‌شود؛ هیچ برندی پیش‌فرض نیست. **اجباری** وقتی GOAL فروش است یا برند باید معرفی شود؛ در بقیه اختیاری.

| فیلد | مثال شکل (نه مقدار) |
|---|---|
| نام برند | همان‌طور که در گفتار گفته می‌شود |
| خط محصول/خدمت | چیز مشخصی که می‌فروشد |
| عبارت حوزه‌ی مخاطب | «پروژه‌های ‹X›»، «تیم‌های ‹Y›» |
| ادعاهای تأییدشده | چیزهایی که برند اثباتشان می‌کند («اورجینال»، «گارانتی»…) |
| کانال سفارش (اختیاری) | پیام، تماس، سایت |
| لحن برند (اگر خاص است) | روی «صدای نویسنده» اعمال می‌شود |

قواعد: فیلد ناقص ← یک بار از کاربر بپرس (اگر حاضر است) وگرنه با `[فرض]` بنویس و در «فرض‌ها» ثبت کن. ادعای تأییدنشده در متن نمی‌آید مگر با وضعیت «نیازمند تأیید برند». جای‌نگهدار (`[برند]` و مانند آن) در خروجی ممنوع است (پل۷).
